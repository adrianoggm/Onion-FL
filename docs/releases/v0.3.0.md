# Onion-FL v0.3.0: Onion-FL Studio

v0.3.0 adds a web app over the framework. `onion_fl serve` opens it at `http://127.0.0.1:8765`. It works on the same files as the command line, so everything it creates or launches stays reproducible from the console.

## What you can do in the Studio

- **Topologies.** Browse `topologies/` with each tree drawn by level, its links and its `topology_id`. Edit a topology level by level (nodes, parents, home datasets, link profiles), with validation and a redraw on every change, and save it as a new file or over the old one.
- **Experiments.** See every scenario of a sweep with its `config_id`. Run the dry-run plan: composition per fog, the parameter groups that travel on each link, the subject roles and warnings. Launch the experiment in simulation or for real, with the number of workers.
- **Runs.** Follow runs with their status (`running`, `finished`, `incomplete`, `failed`) and identity. The views show the composition and the metric series per level: global accuracy and train loss, zone models, divergence and edge scores. Events stream in live while a run is going.
- **Compare.** Compare topologies, scenarios or datasets at any level: mean ± 95% CI over the seeds per round, plus the spread across the nodes of the level.
- **Tutorial.** Read what each experimental axis decides, with every plugin explained and its parameters. Try the dry-run previews: how far each group travels under each sharing policy, how fogs fill as α or β change, and what each network profile costs.

## Also in this release

- `onion_fl plan` and the Studio warn when an aggregator is fed by lossy links and has no `deadline`. In simulation, a lost update would otherwise stall its round, and the run would end `incomplete`. The `four_fogs` example now sets a root deadline.

## Install

```bash
uv pip install --python .venv -e ".[studio]"   # or ".[dev]", which includes it
onion_fl serve --root .                        # --host and --port to change where it listens
```

The Studio has no authentication and listens on `127.0.0.1` by default; it is meant for local use.
