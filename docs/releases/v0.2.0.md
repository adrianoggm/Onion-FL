# Onion-FL v0.2.0: the framework

v0.2.0 replaces the original Flower + MQTT prototype with a framework for hierarchical federated learning experiments. The same experiment runs in a deterministic simulator or as real processes over MQTT, and every run leaves a signed record. The design is in [docs/architecture.md](../architecture.md).

## What you can do now

- **Describe a topology of any depth** in YAML: root, aggregation levels, links with transport, codec and network profile. Each topology gets a `topology_id`, and `onion_fl topology show` draws it as a tree, JSON or Mermaid.
- **Bring datasets declaratively.** Readers and steps in `datasets/*.yaml` turn raw files into one `SubjectData` per subject, which is cached and signed. The release ships descriptors for SWELL (plus a physiology-only one), SWEET and WESAD, and `onion_fl data inspect` warns about features that nearly copy the label.
- **Assign subjects and place clients.**
  - Test, val and train roles are fixed across scenarios, and preprocessing is fitted on the training subjects only.
  - The placement plugins are `mixing(α)` (segregated to fully mixed fogs), `dirichlet`, `label_skew`, `explicit` and `pooled`.
- **Choose what is learned and what travels.**
  - A modular model gives each dataset an adapter, a shared or per-dataset trunk, and a head per task or per dataset.
  - Sharing scopes decide how far each part goes: `fedavg`, `fedper`, `zone`, `independent`, `harmonized` or custom rules.
  - Aggregation is per key (`fedavg`, `mean`, `median`, `trimmed_mean`), followed by a server optimizer (`replace`, `fedavgm`, `fedadam`).
  - Trainers are `standard` and `fedprox`; inits are `random` and `checkpoint`.
- **Run rounds that behave like a network.**
  - Registration is acknowledged; rounds close on quorum and deadline.
  - Late updates are dropped or used in the next round, and participation can be a fraction.
  - Evaluation runs at the edge, at each zone and globally per dataset.
- **Simulate, or run for real.**
  - The simulator has a virtual clock with link latency, bandwidth and loss, and compute and availability models.
  - `onion_fl run --mode real` starts one process per aggregator over MQTT. With full quorum and the same seed, both modes give the same final model.
- **Measure everything.**
  - Each run writes `runs/<run_id>/` with its events, summary and final model, signed with `run_hash`.
  - Each aggregator computes diagnostics: divergence, dataset conflict, drift, participation and fairness. The run recorder adds the traffic per link.
  - `load_runs(...).compare(...)` gives the mean ± CI over seeds, and `onion_fl report` turns it into HTML.
  - Prometheus and OpenTelemetry sinks feed the Grafana dashboard and the Docker stack.
- **Sweep and compare** scenarios from one experiment file, run them in parallel, and get classical baselines (`onion_fl baseline`) on the same test subjects.

## Examples

- `experiments/mix_ab.yaml`: SWELL and SWEET over four fogs, from segregated to fully mixed, three seeds.
- `experiments/swell_reference.yaml`: the reference SWELL setup from before the redesign (physiology, three fogs, the same test subjects and the same subjects per fog).

## Status of results

**No experiment of the new framework has been run on real data in the repository yet.** The datasets are not in git. The descriptors and the reference experiment are checked without data; their parity tests against the old loaders run once `data/` is present. The baselines from before the redesign remain in `results/legacy/` with their caveats.

## Removed

- The old runtime: `clients/`, `brokers/`, `servers/`, `training/`, `federated_architecture.py`, `runtime_protocol.py`, the model and telemetry modules, and their launch scripts and configs.
- The baseline and validation scripts, now `onion_fl baseline` and `onion_fl data inspect`.
- The ECG5000 path, the Pushgateway and the `flwr` dependency.

## Upgrading

Old run folders (`federated_runs/`) and configs (`configs/`) do not carry over. Write an experiment YAML instead (`experiments/swell_reference.yaml` shows the reference setup) and run it with `onion_fl run`.
