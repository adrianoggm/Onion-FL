# Onion-FL v0.4.1: a security fix and silently wrong results

v0.4.1 is a patch on v0.4.0. It closes a hole by which a message on the broker could run code. It also fixes configurations that ran without an error but gave wrong results. Nothing new is added, and no number published with v0.4.0 changes.

## Security

- **A received message could call code** ([#173](https://github.com/adrianoggm/Onion-FL/issues/173)).
  - The real runtime resolved the codec name inside the received bytes through the plugin registry, which accepts `module:attribute`. So anyone who could publish to the broker (Mosquitto without authentication, for example) could make a node import and call a zero-argument function, or crash it.
  - Each runtime now decodes only with the codecs its own links were built from, and anything it cannot decode is recorded as `message.rejected`.
- **`gh.py` could print a token.** When the origin URL did not match, the error printed it with any credential embedded in it.
- **The Studio** reports a missing file by name, not by its local path.
- **CodeQL.** The code-quality alerts on `main` are fixed, with unchanged behaviour. The two false positives and the intentional import cycle between `runner` and `real` are dismissed with their reasons.

## Silently wrong results ([#174](https://github.com/adrianoggm/Onion-FL/issues/174))

- **A meta column could become a feature.** A `subject` or `label` step placed after `features` left its source column in X, so the label could leak into the features.
- **Two dataset entries could load the same dataset.** Their subjects overwrote each other. This is now refused.
- **An attack with the `pooled` placement attacked nobody**, while `data.attack` said it did. Attackers are now chosen among the placed edges; a placement that does not merge picks the same attackers as before.
- **Trainers were anchored to local groups.** The first model an edge gets is whole, so FedProx, Ditto and FedDyn pulled local groups (`fedper`, `lg_fedavg`) towards their start, and FedDyn kept a term on them that never updated. The trainer now sees only the keys its edge shares.
- **Only round-1 participants got the whole model.** A child drawn later (`fraction`), or one whose first model was lost, never got the initial values of its local and zone groups. Every child now gets the whole model the first time it gets one.
- **`compare()` averaged different series.** It treated every row of a level as a node, so the report and the Studio averaged, for example, the global model's score with the edges'. It now also splits by model, source and dataset when they vary.

## Effect on published results

None of the committed numbers change:
- no experiment pairs FedProx, Ditto, FedDyn or MOON with local sharing;
- none uses partial participation or attacks with `pooled`;
- the results tables come from the events, not from `compare()`.

A rerun of a lossy run where an edge first trained after round 1 (`techniques_drift_lossy`, seed 0) gives a bit-identical final model.

The `report.html` plots drawn with the old comparison may average different series.

## Verification

ruff passes. With SWELL, WESAD and a local Mosquitto broker, 896 of the 900 tests pass; the 4 skips are the optional Excel and Parquet readers and SWEET, whose data is not available. The CI of the release pull request runs the suite with a broker and without data.
